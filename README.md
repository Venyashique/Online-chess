# Online Chess

Шахматное веб-приложение на **React + TypeScript + Vite**. Сейчас доступны главная страница и полноценная партия против **Stockfish 19** в браузере. Онлайн-раздел поддерживает два места, подтверждённые сервером ходы и Realtime-синхронизацию через Supabase (этап 4C); обучение пока остаётся заглушкой.

## Запуск

Нужны Node.js **22.12+** (рекомендуется Node.js 24 LTS) и npm.

```sh
npm ci
npm run dev
```

Откройте адрес Vite из терминала, выберите «Играть с компьютером», цвет и сложность, затем нажмите «Начать партию». Случайный цвет определяется заново при каждом старте. Для доступа с другого устройства в вашей сети: `npm run dev -- --host 0.0.0.0`.

`npm ci` подготавливает локальные JS/WASM-файлы Stockfish через `postinstall`. `predev` и `prebuild` повторяют этот шаг, поэтому запуск и сборка работают и после установки с `--ignore-scripts`. Генерируемая папка `public/engine` не хранится в Git.

## Что работает

- 2D-доска с SVG-фигурами, координатами, выбором нажатием, перетаскиванием мышью и касанием. Для клавиатуры: Tab, стрелки, Enter/Пробел; Esc отменяет выделение.
- Правила `chess.js`: легальные ходы, взятия, шах, мат, пат, рокировка, взятие на проходе и выбор превращения в ферзя/ладью/слона/коня.
- Игра белыми, чёрными или случайным цветом. Ваши фигуры всегда снизу. При игре чёрными Stockfish делает первый ход.
- Три действующие сложности: «Лёгкий», «Средний», «Сложный».
- Асинхронный ответ Stockfish в Worker и состояние «Компьютер думает…». Во время ответа нельзя ходить за другую сторону или сделать второй ход.
- История в SAN, очередь, шах, результат, новая партия. Новая партия и выход со страницы отменяют вычисления; устаревшие ответы игнорируются.
- Обработка ошибок загрузки/расчёта с кнопкой повторной попытки.

Настройки цвета и сложности применяются при старте новой партии; изменение формы не меняет текущего соперника посреди расчёта. Перезагрузка или выход из раздела сбрасывают партию. Ничьи при недостатке материала, троекратном повторении и по правилу 50 ходов фиксируются автоматически по результату `chess.js`, без отдельной процедуры заявления.

## Сложность

| Уровень | Stockfish Skill Level | Максимальная глубина | Лимит расчёта |
| ------- | --------------------: | -------------------: | ------------: |
| Лёгкий  |                     0 |                    4 |        150 мс |
| Средний |                     8 |                   10 |        650 мс |
| Сложный |                    20 |                   18 |       1800 мс |

Ограничения действуют совместно: поиск заканчивается при достижении глубины или времени. `Skill Level` ниже 20 включает собственный механизм ослабления Stockfish, выбирающий менее сильные варианты; уровни не являются просто задержкой ответа. Это практические пресеты, **не калиброванный Elo**. Реальная сила зависит от позиции, устройства и lite-сети. Предусмотрена отдельная таблица настроек для будущей шкалы силы.

## Архитектура

```text
src/
  app/                          # приложение, hash-навигация, общие стили
  pages/                        # главная страница
  features/
    computer/
      model/useComputerGame.ts  # человек/компьютер, настройки, жизненный цикл
      ComputerPage.tsx          # сборка экрана партии
    online/                     # repository/service, identity, realtime и online UI
    learning/                   # заглушка
  shared/
    chess/
      domain/                   # ChessGame, типы, правила и история
      session/                  # локальная сессия и текстовый статус
      engine/                   # интерфейс ChessEngine, UCI-адаптер, сила
      ui/                       # Board2D, SVG-фигуры, тема, превращение
    ui/                         # общие элементы приложения
  test/                         # настройка Vitest
scripts/prepare-stockfish.mjs    # подготовка только выбранной сборки движка
```

`ChessGame` — единственный адаптер `chess.js`. Он хранит позицию с полной историей и проверяет **все** ходы, включая ответы компьютера. Снимок включает исходную FEN, текущую FEN, историю, фигуры, очередь, допустимые действия и результат.

`useGameSession` управляет локальными действиями и превращением без зависимости от Stockfish. `useComputerGame` добавляет владение цветом, настройки и асинхронного соперника. `ChessEngine` получает исходную позицию и последовательность ходов, возвращает `{ from, to, promotion? }`; он не изменяет партию. Адаптер доступен из `shared/chess/engine` для будущих задач обучения, без реализации анализа сейчас.

`Board2D` получает снимок, обработчик хода, ориентацию, блокировку и тему. Он не импортирует движок и не вычисляет правила. Будущий `Board3D` сможет использовать те же данные и действия. `BoardTheme` по-прежнему позволяет независимо заменить цвета/подсветку и `PieceView`. Новых тем и 3D-библиотек нет.

Подробности выбора движка, отмены, публикации и ограничений: [docs/stockfish.md](docs/stockfish.md).

## Проверки и сборка

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

`npm run test:watch` — режим наблюдения. Автотесты покрывают правила, навигацию, интерфейс, владение цветом, все сложности, отмену, поздние ответы, завершение и UCI-протокол. Расчёты в unit-тестах заменены управляемым адаптером/Worker, поэтому тесты не зависят от скорости реального Stockfish.

Дополнительно production-версия проверена в Chromium на ширинах 1440, 390 и 320 px с реальным WASM-движком. Этот разовый browser-прогон не входит в `npm test`.

## Публикация

Результат `npm run build` — папка `dist`. Нужен обычный статический хостинг, корректно отдающий `.js` и `.wasm` (`application/wasm`). Весь `dist/engine` должен публиковаться вместе с приложением. Сборка учитывает Vite `base`, включая путь Worker. COOP/COEP и сервер вычисления ходов не нужны. Если хостинг использует CSP, он должен разрешать Worker того же origin и WebAssembly (`worker-src 'self'`, `script-src` с `'wasm-unsafe-eval'` и разрешением скриптов приложения).

## Онлайн-раздел (4C)

Для работы в облаке нужны отдельный Supabase-проект Online Chess, migrations 4A/4B, Edge Function `submit-online-move` и **новая migration 4C** для Database Broadcast. По данным пользователя, 4B уже проверен на реальном проекте. Код и SQL 4C проверены локально; migration 4C и внешние изменения в этой задаче не выполнялись.

Браузерные переменные остаются прежними:

```sh
cp .env.example .env.local
```

```dotenv
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_ANON_KEY=<public-publishable-or-anon-key>
```

URL берётся в Supabase Connect / Project Settings → Data API; publishable (`sb_publishable_…`) или legacy anon/public key — в Project Settings → API Keys. Не используйте service_role/secret key в `VITE_*`. `.env.local` игнорируется Git. После изменения настроек перезапустите Vite / пересоберите production.

Создатель выбирает цвет и получает своё место. Другой браузер открывает ссылку `/#/online/<uuid>` и нажимает «Занять свободный цвет». Присоединение, позиция, история и очередь обновляются автоматически; чужие фигуры и очередь блокируются. После reload своё место восстанавливается из отдельного случайного ключа в localStorage. Без ключа занятое место вернуть нельзя. Третий клиент остаётся зрителем.

Каждый ход проходит **авторитетную проверку `ChessGame`/chess.js в Supabase Edge Function**, затем закрытый для браузера RPC атомарно дописывает один ход и увеличивает `version`. Готовая FEN от клиента не принимается. При конфликте загружается актуальная позиция без автоматического повтора хода. До развёртывания Edge Function небезопасной клиентской записи нет.

SQL 4B: `supabase/migrations/202610160002_online_seats_and_moves.sql`. Серверный код и lockfile: `supabase/functions/submit-online-move/`. Подробная схема, RPC, безопасность и согласуемый порядок развёртывания — [docs/online-4b.md](docs/online-4b.md). Документ [4A](docs/online-4a.md) сохранён как история предыдущего этапа.

Старые партии 4A остаются доступны для просмотра: в них не было credential владельца и безопасно назначить его задним числом нельзя. В новых партиях сервер хранит SHA-256 ключей, а публичные ответы не содержат hashes. Прямое чтение/изменение таблицы закрыто, RLS сохранён.

`npm test` включает локальный PostgreSQL/PGlite, права RPC, реальный обработчик серверных ходов, browser identity и UI; внешний Supabase тестам не нужен. Дополнительно проверен Deno entrypoint и production-клиент в Chromium на 1440/390/320 px с локальной имитацией HTTP-границы Supabase.

Realtime использует публичный Broadcast `online-game:<uuid>` с минимальным сигналом `{game_id, version}`. Подтверждённое состояние перечитывается через безопасный RPC. Закрытая `online_games` не публикуется, RLS и права не ослабляются. Поддельное уведомление не меняет права или позицию. После reconnect/возврата во вкладку выполняется resync; видимая вкладка дополнительно сверяется каждые 30 секунд. Кнопка ручного обновления остаётся резервной.

SQL 4C: `supabase/migrations/202610160003_online_version_broadcast.sql`. Механизм, границы безопасности, тесты, ограничения и точные шаги включения после подтверждения: [docs/online-4c.md](docs/online-4c.md). **Не добавляйте `online_games` в Realtime publication.**

Проверки 4C: TypeScript, 143 теста, production build; Chromium 1440/390/320 с локальной имитацией HTTP/WebSocket и PostgreSQL, включая автоматические ходы двух игроков, reconnect и зрителя без credentials. Реальный Realtime Supabase в этой задаче не проверялся.

Live-presence, аккаунты, рейтинг, часы, обучение и 3D не добавлены. Для публичного запуска ещё нужны лимиты API/Realtime и политика утраты/отзыва ключей.
