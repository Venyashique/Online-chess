# Браузерный соперник

## Выбор интеграции

Используется npm `stockfish@19.0.1`, сборка **Stockfish 19 lite single-threaded** из проекта Nathan Rugg / Chess.com, рекомендуемая самим upstream для обычных браузерных приложений.

Сравнивались опубликованные upstream варианты:

| Сборка                    | Практический компромисс                                            |
| ------------------------- | ------------------------------------------------------------------ |
| Full WASM                 | Более сильная сеть, но около 94 МБ и более тяжёлая первая загрузка |
| Многопоточная WASM        | Требует cross-origin isolation, SharedArrayBuffer, COOP/COEP       |
| Lite single-threaded WASM | Около 1,8 МБ с JS, отдельный Worker, обычный статический хостинг   |
| ASM-JS                    | Не требует WASM, но медленнее и слабее; резервный вариант upstream |

React-обёртка не требуется: документированный API движка — классический Worker и текстовый UCI через `postMessage`. Это позволяет обновлять движок независимо от React и renderer. Официальный README пакета: https://github.com/nmrugg/stockfish.js/tree/v19.0.1.

Весь npm-пакет содержит несколько сборок и занимает около 196 МиБ после распаковки. В `public/engine` и `dist/engine` копируются **только** JS/WASM lite single-threaded, GPL и сведения об исходниках. `stockfish` закреплён точной версией; скрипт подготовки проверяет её, чтобы обновление не оставило устаревшие имена файлов.

## Контракт и поток данных

1. `ChessGame` выдаёт исходную FEN и историю координатных ходов.
2. `useComputerGame` проверяет, что ходит компьютер и партия ещё идёт.
3. `StockfishEngine.chooseMove(position, strength, signal)` создаёт Worker при первом обращении.
4. `uci` → проверка поддержки `Skill Level` → `ucinewgame` → настройки → `isready` → `readyok`.
5. Адаптер отправляет `position fen … moves …` и `go depth … movetime …`. Полная история позволяет движку учитывать повторения.
6. `bestmove` преобразуется в `MoveAction`. Ответ проверяется на актуальность и передаётся в `ChessGame.move`, а не применяется к доске напрямую.

Завершённый поиск освобождает обработчик отмены и таймер; Worker повторно используется для следующего хода той же партии. Используется Hash 16 МиБ, один вычислительный поток. Нет искусственного ожидания ради сложности.

## Отмена и ошибки

UCI не присваивает `bestmove` идентификатор запроса. Поэтому отмена не ограничивается командой `stop`: активный Worker **завершается**, его обработчики снимаются, Promise отклоняется с `AbortError`. Следующее обращение создаёт новый Worker. Это исключает смешение старого и нового вывода UCI. Даже сохранённый callback старого транспорта проверяет идентичность Worker.

Слой сессии также проверяет номер партии, номер запроса, AbortSignal и текущую FEN. Номер партии увеличивается синхронно при нажатии «Новая партия», до запуска React effects. Защита работает и с адаптером, который игнорирует отмену, включая новую партию с точно такой же FEN.

Выход со страницы и размонтирование отменяют поиск и освобождают Worker. Для мата, пата и ничьих поиск не запускается. При ошибках Worker, несовместимом UCI, неверном ходе или тайм-ауте партия остаётся целой; интерфейс предлагает повторить расчёт или начать новую партию. Инициализация ограничена 20 секундами, ожидание результата — временем пресета плюс 10 секунд запаса.

## Ограничения

- Требуются современные браузерные WebAssembly и Web Worker. Автоматической подмены на случайные ходы нет.
- Lite использует меньшую сеть. Даже ограниченный Stockfish может быть сложным для абсолютного новичка; пресеты не обозначают достоверные рейтинги 600/1200/2000. Для будущей Elo-шкалы понадобится игровая калибровка.
- Браузер может замедлить/приостановить Worker в фоновой вкладке. Выводится ошибка тайм-аута с повторной попыткой, если ответ не получен.
- Нет сохранения партии, анализа, подсказок или обещания силы по рейтингу.
- Автоматические UI-тесты не запускают реальный Stockfish: они проверяют оркестрацию независимо от производительности. Работа настоящего JS/WASM дополнительно проверяется в браузере.
